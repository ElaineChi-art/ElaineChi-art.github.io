量化交易的第一步：把散落的市場資料變成一張乾淨的表

技能實驗室・每日課程 2026-08-20 約 8 分鐘 對應真專案主題：爬蟲入門學程
⚡ 30秒白話版

量化交易的第一步，不是寫一個聰明的策略，而是把散落各處的市場資料，收成一張乾淨、對得起來的表。真實世界的資料很亂：股價在這個網站、財報在那個公告、成交量又是另一種格式，日期有的寫「2026/8/20」、有的寫「20260820」，還常常缺幾天、混進錯字。你不先把這些抓下來、洗乾淨、對齊到同一個時間軸，後面再厲害的策略都是建在沙上。這件事的核心心法就一句話：垃圾進、垃圾出（garbage in, garbage out）——策略的準確度，常常不是輸在不夠聰明，而是輸在資料根本沒對齊。所以「爬蟲＋資料清洗」不是量化的雜活，而是整個系統的地基：一張每一列都是「同一個標的、同一個時間點」的乾淨表，就是你之後所有回測與策略的立足點。

SLIDE 1 簡報講解

這張圖在講的是，量化交易的第一步不是寫策略，而是把散落各處的市場資料，收成一張乾淨、對得起來的表。左邊是原始資料的樣子：來源很多，有股價、成交量、財報、新聞，每個來源的日期格式、欄位名稱、缺漏都不一樣，硬拼在一起就會對錯行。中間這條管線做三件事：抓下來、洗乾淨、對齊時間，把每一列都變成同一個標的、同一個時間點的一筆紀錄。右邊才是你熟悉的乾淨表，一行一個時間點，欄位固定、型別一致、沒有缺漏，策略跟回測都建在它上面。所以整張圖的主張是，量化的準確度不是贏在策略多聰明，而常常是輸在資料沒對齊——垃圾進，就垃圾出。

壹、這是什麼

量化交易的第一步，其實是一件很不「量化」的苦工：把散落在各處、格式亂七八糟的市場資料，收成一張乾淨、每一列都對得起來的表。大家想到量化，腦中浮現的通常是聰明的策略、漂亮的績效曲線，但那些都是後面的事。在那之前，你手上只有一堆原始資料：股價在某個網站、成交量在另一個檔案、財報藏在公告 PDF、市場情緒又躲在一堆新聞裡。這些資料來源不同、格式不同、更新頻率不同，甚至連「日期」都各寫各的——有的寫「2026/8/20」，有的寫「20260820」，有的乾脆只給「8-20」。你要做的，就是把它們一筆一筆抓下來、洗乾淨、對齊到同一條時間軸上。

這件事拆開來就是三個動作：抓下來、洗乾淨、對齊時間。「抓下來」靠的是爬蟲（自動把網頁或介面上的資料撈回本地的程式）或官方提供的 API（一種讓程式直接跟服務要資料的正式管道）；先把原始資料原封不動存起來，不要邊抓邊改。「洗乾淨」是資料清洗：統一日期與單位格式、把缺漏的日子補上或標記、去掉重複的列、把「數字被當成文字」這種型別問題改對。「對齊時間」是最容易被低估的一步——把不同來源用同一條時間軸接起來，讓最後那張表的每一列都代表「同一個標的、同一個時間點」的一筆完整紀錄。做完這三步，你手上才會有一張可以直接餵給策略和回測的乾淨表。

貳、為什麼業界在乎

業界在乎這一步，是因為策略的準確度，常常不是贏在多聰明，而是輸在資料沒對齊——這在資料領域有個很老實的說法叫「垃圾進、垃圾出」（garbage in, garbage out）：你餵進去的資料是髒的，再厲害的模型也只會又快又穩地算出一個錯的結論。量化尤其吃這一套，因為它的每一個決策都是機器根據資料自動下的，人不會在中間用常識擋一下。如果某一天的成交量因為抓取失敗變成 0、或某檔股票的除權息沒有調整、或兩個來源的日期差了一天沒對齊，策略不會「覺得怪怪的」，它會照著錯的數字算下去、下出錯的單。所以在真實的量化團隊裡，抓資料、清洗、對齊這件「雜活」，其實是整個系統最底層的地基，地基歪一公分，樓上全垮。

這也正好呼應 104 人力銀行《AI 人才趨勢報告》一直強調的「打通完整應用情境」——不要只會孤立地學一個技術點，而要能把一整條流程串起來。爬蟲和資料清洗，就是「資料應用」這條完整情境的最前段：一個只會套現成乾淨資料集、跑跑模型的人，跟一個能從零把散落的真實資料抓下來、洗成能用的樣子、再接到後面的分析的人，職場成熟度差很多。前者交的是一段跑在乾淨資料上的程式，後者交的是一條能持續把混亂真實世界變成可用資料的管線。對想做全端或量化的人來說，「我能自己搞定資料從哪來、怎麼變乾淨」本身就是很有說服力的能力證明。

參、實務怎麼用

放到玉山、國泰這類金融科技，或一個要處理市場資料的量化／資料職缺，這件事大致會長這樣。假設我要做一個「觀察某些標的每日行情」的小系統，第一步我會優先找官方或正式的 API——例如證交所、櫃買中心這類單位提供的公開資料介面，用 Python 定時去要資料；只有在沒有 API 的情況下，才退而用爬蟲去解析網頁。抓回來的原始資料，我會原封不動先存一份（例如存成一個個帶日期的原始檔），這樣之後清洗邏輯改了，還能從原始資料重跑，不會把來源弄髒。第二步清洗，我通常會用 pandas（Python 處理表格資料最常用的工具）把資料讀成一張表，統一日期格式、把數字型別轉對、處理停牌或假日造成的缺值、去掉重複列。第三步對齊，我會用日期當索引，把股價、成交量這些不同來源合併（join）成一張以時間為主軸的寬表，確認每一列都是同一天、同一標的的完整一筆，才交給後面回測。

對我這種法律金融跨域背景的人，這一步其實特別有共鳴，因為它本質上是一套「資料的盡職調查與勾稽」。做法遵、做盡職調查時，你最在意的從來不是「數字好不好看」，而是「這個數字的來源可不可靠、口徑一不一致、對不對得起來」——同一家公司在兩份文件上的數字兜不攏，那就是要查清楚的紅旗。資料清洗的精神一模一樣：兩個來源的成交量對不上、某天的價格明顯異常、日期兜不齊，這些都是「先別急著算，先查清楚」的訊號。把「勾稽、可回溯、有憑有據」這套我本來就熟的直覺，搬到資料工程上，反而是我相對別人有優勢的地方——尤其在金融場景，資料錯了動到的是真金白銀和法遵責任，這種「不放過對不齊」的龜毛，正是他們要的。

肆、常見誤區或追問延伸

最容易踩、也最容易在面試被戳破的坑，是把「有一張表」當成「有一張乾淨、能用的表」。很多人抓完資料、拼成一個 DataFrame 就以為完工了，但真正的魔鬼藏在你看不到的地方：缺值怎麼處理？除權息有沒有還原？兩個來源的時區與收盤時間對得上嗎？舉個量化最經典、也最致命的錯——未來函數（look-ahead bias，在回測某一天時，不小心用到了那一天之後才會知道的資訊）。比方說你用「經過事後修正的財報數字」去回測發布當天的決策，績效會漂亮得不真實，因為你偷看了未來。這種錯不會報錯、不會當機，它只會給你一條假的漂亮曲線，等你真的拿去交易才發現全是幻覺。所以「資料乾不乾淨」的真正考題，不是欄位齊不齊，而是「在每一個時間點，你的資料是不是只包含那個當下真的能拿到的資訊」。

另一個誠實要先想清楚的分界，是「爬蟲抓得到」不等於「你可以拿去用」。技術上能不能抓，和法律上、規範上能不能抓、能不能用，是兩件事：很多網站的使用條款禁止自動化抓取，有些資料有著作權或授權限制，抓得太兇還可能對人家伺服器造成負擔。這點我因為法律背景反而會特別留意——實務上會優先用官方 API 和公開授權的資料源、控制抓取頻率、看清楚 robots.txt 與使用條款，而不是有技術就硬爬。不過我要誠實說：這一題我目前主要是在自己的練習專案上，用過官方公開資料 API 加上 pandas 做過抓取與清洗的完整小流程，原理和常見的坑我講得清楚；但還沒在真正生產規模、要每天穩定更新、處理大量標的與異常監控的資料管線裡實戰過。被追問到那個層級時，我會誠實說明我掌握的原理與會怎麼上手驗證，而不是硬掰經驗。

寫策略之前，先把資料收乾淨——量化真正的第一步，是把混亂真實世界裡散落的市場資料，變成一張每一列都對得起來的乾淨表。因為到頭來，策略再聰明，也贏不過餵給它的資料有多乾淨：垃圾進，就垃圾出。

🎤 面試官可能怎麼問
  1. 「你會怎麼開始做一個量化交易的資料流程？」 👉 這題其實在問：你知不知道量化的第一步是資料工程，而不是一上來就寫策略。 她可以怎麼答：我會先把資料搞定，再談策略。第一步是抓下來，優先找官方 API，沒有才用爬蟲，抓回來的原始資料先原封不動存一份。第二步是洗乾淨，用 pandas 統一日期和單位格式、把型別轉對、處理停牌或假日的缺值、去掉重複。第三步是對齊時間，用日期當索引把不同來源合併成一張以時間為主軸的表，確認每一列都是同一天、同一標的的完整一筆。做完這三步才會有一張能餵回測的乾淨表。因為策略的準確度常常不是贏在多聰明，而是輸在資料沒對齊，垃圾進就垃圾出。
  2. 「資料清洗你具體會做哪些事？」 👉 這題其實在問：你是真的洗過髒資料，還是只用過現成的乾淨資料集。 她可以怎麼答：主要是統一格式、補缺、去重、改型別這幾類。日期格式各家不一樣，要統一成同一種；數字常常被當成文字讀進來，要轉成數值型別；停牌日、假日會有缺值，要決定是補前一天、還是標記為缺、還是整列丟掉，這個決定會影響後面計算；重複的列要去掉；還有明顯的異常值，比如成交量突然變 0，要先查是真的還是抓取失敗。重點是每一個處理都要想清楚它對後面計算的影響，而不是隨手填一個 0 或平均值就算了。
  3. 「什麼是未來函數（look-ahead bias）？你怎麼避免？」 👉 這題其實在問：你懂不懂回測最經典、最會給人假績效的那個陷阱。 她可以怎麼答：未來函數就是在回測某一天的決策時，不小心用到了那一天之後才會知道的資訊。最典型的例子是用事後修正過的財報數字去回測發布當天的決策，或是用當天收盤後才確定的價格去做當天盤中的判斷。它可怕的地方是不會報錯，只會給你一條漂亮到不真實的績效曲線，等你真的拿去交易才發現是幻覺。避免的核心原則是，在每一個時間點，資料只能包含那個當下真的能拿到的資訊，所以我會特別注意資料的時間戳記到底是什麼時候真正可得的。
  4. 「你為什麼優先用 API 而不是直接爬？」 👉 這題其實在問：你懂不懂爬蟲的技術能力和它的法律、規範邊界是兩回事。 她可以怎麼答：因為 API 是資料方正式開放的管道，格式穩定、比較不會突然改版壞掉，而且授權關係清楚。爬蟲雖然技術上抓得到，但抓得到不等於可以拿去用：很多網站的使用條款禁止自動化抓取，有些資料有著作權或授權限制，抓太兇還會給人家伺服器造成負擔。我因為法律背景會特別留意這塊，實務上會優先用官方 API 和公開授權的資料源、控制抓取頻率、看清楚 robots.txt 和使用條款，而不是有技術就硬爬。
  5. 「你實際做過的資料流程到什麼程度？」 👉 這題其實在問：你的經驗是紙上談兵還是真的動過手，而且你誠不誠實。 她可以怎麼答：老實說我目前主要是在自己的練習專案上，用官方公開資料 API 加上 pandas 做過從抓取、清洗到對齊時間的完整小流程，所以資料工程的原理和常見的坑，像缺值處理、時間對齊、未來函數，我是講得清楚的。但我還沒在真正生產規模、要每天穩定更新、處理大量標的還要做異常監控的資料管線裡實戰過。如果這份工作會碰到那個層級，我會先讀懂團隊現有的資料流程和資料品質檢查是怎麼做的，從跟著跑一次、看它每一關在驗什麼開始上手，而不是一來就自己另開一套。
