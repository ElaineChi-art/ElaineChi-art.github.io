大型語言模型的能力邊界：它真的「理解」還是很會「猜下一個字」

技能實驗室・每日課程 2026-07-27 約 6 分鐘 對應真專案主題：LLM大型語言模型
⚡ 30秒白話版

大型語言模型的本質，是「給一段文字、猜下一個最可能的字」，一個字一個字接出整段回答。它並沒有我們以為的那種「理解」，只是資料和模型都夠大，猜字這件事逼它學會了語法、事實關聯和推理的模式，規模到了才看起來像懂。這個本質決定了它的能力邊界：它會流暢地講出錯的內容（幻覺）、知識有截止日、沒有即時查核事實的機制。所以面試時的正確講法不是「它很聰明」，而是「它很會猜，但答得流暢不等於答得對，用它就要有人為輸出把關」。

SLIDE 1 簡報講解

這張圖在講的是，大型語言模型到底在做什麼、以及它做不到什麼。左邊是核心：它其實只是在「預測下一個字」，給一段文字、算出最可能接哪個字，再把新的一串丟回去繼續猜，整段回答就是一個字一個字接出來的，所以本質上是一台超強的文字接龍機器，不是資料庫。中間解釋為什麼看起來像理解：資料和模型都夠大時，猜對下一個字這件事會逼它學會語法、事實關聯和推理模式，規模過門檻還會冒出沒被特別教的能力，但它抓到的是統計規律，不是真的懂。右邊是重點，也是它的能力邊界：它會流暢地講錯（幻覺）、不知道自己對不對、知識有截止日。一句話：答得流暢不等於答得對，用它就要有人把關。

壹、這是什麼

大型語言模型（Large Language Model，一種用海量文字訓練、專門預測「下一個字」的巨大神經網路）的核心動作，其實只有一件事：預測下一個字。你給它一段文字，它算出「接下來最可能出現哪個字」，把那個字接上去，再拿加長後的一整串重新丟回去，繼續猜下一個、再下一個。你看到的一整段流暢回答，就是這樣一個字一個字接出來的。它不是在查一個資料庫，也不是在搜尋，而是在算機率。

釐清這件事，才答得清「它到底懂不懂」。它並沒有我們日常說的那種「理解」——它沒有一個心裡明白的意思，再把意思轉成文字。它是反過來的：先學會了「這種上下文後面通常接什麼」的統計規律，然後照著規律把字接出來。之所以看起來像懂，是因為當訓練資料夠多、模型夠大時，「把下一個字猜準」這個目標會反過來逼模型學會語法、常識、事實之間的關聯，甚至一部分推理的模式。規模到一定程度，還會冒出一些沒有被特別教過的能力，業界叫它湧現（emergence，能力隨規模跨過某個門檻才突然出現的現象）。但這一切的底層，仍然只是「很會接下一個字」。

貳、為什麼業界在乎

業界在乎「它是理解還是猜」，是因為這條界線直接決定你敢把它放進產品的哪一段。如果你以為它「懂」，你會傾向相信它的輸出、直接拿去用；一旦認清它是「很會猜、但不保證對」，你就會在它前後補上防線。這正是「幻覺」（hallucination，模型在沒把握時仍流暢地生成看似合理、實際錯誤的內容）為什麼是每個 LLM 應用都要處理的頭號問題——它不會在不確定時說「我不知道」，而是照樣把最像答案的字接出來。這是常識性的技術知識，也寫在 OpenAI、Anthropic 等官方模型說明文件的使用限制章節裡：模型可能產生不準確的資訊，輸出需要人為查核。

對求職者來說，這一課的價值在於「打通完整應用情境」，而不是背一個定義。104 人力銀行《AI 人才趨勢報告》就建議求職者培養端到端的應用能力，而非零散學單一技能。放到 LLM 上，面試裡光說「它會猜下一個字」只是及格；能接著講「所以它會幻覺、知識有截止日、沒有即時查核，因此我在設計功能時會怎麼補上把關機制」，才是一條能被追問也答得下去的完整脈絡。你不需要會從零訓練一個模型，但要能說清楚它的能力從哪來、邊界在哪，以及這對產品設計代表什麼。

參、實務怎麼用

放到金融場景，這條界線的實務意義非常直接：LLM 可以幫你「起草」，但不能「拍板」。假設我在國泰或玉山，任務是做一個內部小工具，讓客服人員把一段冗長的保單條款丟進去、請模型摘要重點。這個用法安全，因為原文就在旁邊、人可以核對。但如果反過來，讓模型直接回答客戶「這個理賠條件你符不符合」，就危險了——它可能把一條不存在的條款講得頭頭是道（幻覺），而金融業對這種錯誤是零容忍的。同一個模型，差別只在「它的輸出後面有沒有人為或規則的把關」。

對我這種法律金融跨域背景的人，能加分的地方剛好在這裡。我知道 LLM 的輸出是「算機率接出來的」、不是「查法條查出來的」，就會自然地問對問題：這段摘要有沒有漏掉對客戶不利的但書？模型引用的條款編號是不是它編的？在合規流程裡，這種「AI 起草、人工複核」的分工要怎麼留下紀錄、由誰負最後的責任？這正好落在技術和法遵的交界處——技術端我懂它為什麼會錯，法遵端我知道錯了誰要扛。這種能把「模型會幻覺」翻譯成「所以流程要這樣設計」的能力，比會不會調 API 更難被取代。

肆、常見誤區或追問延伸

最容易答錯的地方，是把「幻覺」當成一個可以修掉的 bug。它不是 bug，是這套機制的副產品。模型的工作就是「不管有沒有把握，都接出最像答案的下一個字」，它本來就沒有一個「我不確定，所以停下來」的內建開關。所以正確的說法不是「等技術成熟就不會幻覺了」，而是「我們用工程手段去壓低它、去接住它」——例如讓它去查外部資料再回答（也就是之後會學到的 RAG）、要求它附上出處、或在高風險場景一律讓人複核。面試官問到這題，想確認的是你知不知道「幻覺是機率生成的必然，只能管理、不能根除」。

另一個要小心的追問，是「它答得很有自信，是不是就比較可信」。不是。模型輸出的流暢度和它的正確性沒有必然關係——它對錯誤答案一樣可以講得斬釘截鐵，因為「講得順」本來就是它最擅長的事。還有一個常被忽略的點是知識截止日（knowledge cutoff，模型訓練資料只到某個時間，之後發生的事它不會自己知道）：問它訓練之後才發生的事，它可能自信地給你一個過時或編造的答案。至於各家模型確切的截止日期、以及不同的幻覺抑制技術細節，我目前是理解到原理層次、還沒有實際上線調校過，被追問細節我會誠實說明我理解的主線、而不是硬掰一個數字。

大型語言模型不是懂了才回答，是很會猜才顯得像懂——記住這句，你就知道什麼時候該信它、什麼時候該親手為它把關。

🎤 面試官可能怎麼問
  1. 「你會怎麼跟非技術的同事解釋，大型語言模型到底在做什麼？」 👉 這題其實在問：你自己是不是真的懂它的本質，而不是只會用。 她可以怎麼答：我會說它本質上是一台超強的「文字接龍」機器。你給它一段文字，它算出下一個最可能的字、接上去，再把加長後的一整串丟回去繼續猜，一整段回答就是這樣一個字一個字接出來的。所以它不是在查資料庫，是在算機率。理解這點很重要，因為它決定了我們該不該直接相信它的輸出。
  2. 「那它到底算不算『理解』我們的問題？」 👉 這題其實在問：你能不能講清楚「像理解」和「真理解」的差別。 她可以怎麼答：我會說它沒有我們日常那種理解。它不是先懂了意思再轉成文字，而是先學會了「這種上下文後面通常接什麼」的統計規律，再照規律接字。之所以看起來像懂，是因為當資料和模型都夠大，把下一個字猜準這個目標會逼它學會語法、常識和一部分推理模式，規模到了甚至會冒出沒被特別教的能力。但底層仍然只是很會接字。
  3. 「什麼是幻覺？為什麼不能直接把它修掉？」 👉 這題其實在問：你知不知道幻覺是機制的必然，不是一個 bug。 她可以怎麼答：幻覺是模型在沒把握時，仍然流暢地生成看起來合理、實際上錯的內容。它不能被直接修掉，因為模型的工作就是「不管有沒有把握都接出最像答案的字」，本來就沒有一個「我不確定就停下來」的內建開關。所以我們是用工程手段去管理它，例如讓它查外部資料再回答、要求附出處、高風險場景一律人工複核，而不是期待它某天不再幻覺。
  4. 「如果要把 LLM 放進金融產品，你會擔心什麼、怎麼設計？」 👉 這題其實在問：你能不能把「模型會錯」翻成具體的產品與流程決策。 她可以怎麼答：我的原則是讓它負責「起草」、不負責「拍板」。像摘要保單條款這種原文就在旁邊、人能核對的用法很安全；但讓它直接回答客戶符不符合理賠條件就危險，因為它可能把不存在的條款講得頭頭是道，而金融業對這種錯零容忍。我會設計成 AI 起草、人工複核，並且留下誰複核、由誰負最終責任的紀錄。差別不在模型多強，而在輸出後面有沒有把關。
  5. 「模型答得很有自信，是不是就比較可信？還有知識截止日是什麼？」 👉 這題其實在問：你有沒有意識到流暢度不等於正確、以及時效性的坑。 她可以怎麼答（誠實的答法）：不是。流暢度跟正確性沒有必然關係，它對錯誤答案一樣可以講得斬釘截鐵，因為講得順本來就是它最擅長的事。另外知識截止日是指它的訓練資料只到某個時間，之後發生的事它不會自己知道，可能自信地給你過時或編的答案。至於各家模型確切的截止日期和不同的幻覺抑制技術細節，我目前是理解到原理層次、還沒實際上線調校過，被追問細節我會誠實說明我懂的主線。
